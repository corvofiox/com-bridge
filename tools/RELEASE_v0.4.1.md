# Com Bridge v0.4.1

键鼠跨屏的手感修复 + 游戏内不再误穿。功能集与 v0.4.0 一致（一套键鼠控制两台 Windows、
副机音频汇到主机一起播放、剪贴板同步、静默自启、Ctrl+Alt+Esc 逃生通道），这一版只修手感。

## 最要紧的一个：副机边缘"粘滞"

从第一版起就存在的一个注入缺陷。表现是：光标在副机靠主机那一侧的边缘附近，
**往主机去很顺畅，往副机里回头拉很粘滞，得用力拉一下才动**；副机桌面左侧的
快捷方式、文件夹因此特别难点。

原因是注入坐标的换算方式。鼠标定位用的是 `MOUSEEVENTF_ABSOLUTE`，像素坐标要先
换成 0~65535 的定点值，Windows 再换回像素。原来用的换算（照搬 Deskflow）在
1920 宽的屏上几乎无损，但在副机 **4480×1600** 的桌面上会把 39 个像素压成同一个
点 —— 相邻两个像素对应同一个定点值，于是"再往右一像素"这个请求永远落回原处：

```
[agent] inj dx=1 (14,771) -> (14,771)     ← 连续几十条，钉在 x=14 上 1.5 秒
```

只有攒够较大位移才跳得过坏点，这就是"用力拉才行"。而进入副机的落点固定在离边
12px，最先踩到的坏点正好是 13 / 15，所以症状全集中在边缘。

修法：把换算改成 Windows 变换的**精确逆**（向上取整），并在 1920 / 4480 / 3840 /
2560 / 7680 / 1366 等宽度上**逐像素穷举**验证往返无损。修复后同一个动作 1:1 跟随。

## 第二个：回传时的长时间卡顿

从副机回主机的那一刻，回传判定会被同一批积压事件反复触发 —— 真机日志里同一手势
在 42ms 内触发 **145 次**，每次都要重新隐藏一次光标（单次约 50ms），累计约 7 秒。
这段时间里重新进副机会发现光标迟迟不出现。

现在**一轮穿越只回传一次**，之后积压的陈旧位移直接丢弃（它们比真实时间晚
0.15~0.3 秒，主机的物理鼠标早已走过同样的路程）。

## 新功能：全屏程序（游戏）时不再误穿

以前玩游戏时把鼠标推到屏幕边就会把键鼠交给副机。现在前台是**别的进程的全屏窗口**
（游戏 / 播放器 / 远程桌面）时，主机不进入穿越状态：

- 单块屏上的最大化窗口**不算**（正常办公不受影响），无边框全屏游戏会被拦；
- 排除桌面 / 任务栏等外壳窗口，点在空桌面上不会误拦；
- 只拦"主机 → 副机"方向，已经在副机上时回主机仍然一碰就走。

## 手感调整

副机回主机保持"**一碰就走**"（抵边 + 朝主机方向，不再需要推够距离）。主机进副机
用原设定（光标抵到最外两列 + 连续两帧外向），极慢的推法可能需要稍微果断一点。

## 升级

两台机器都要换成本版 exe，替换后重新启动程序即可；配置（`%LOCALAPPDATA%\ComBridge\config.json`）
无需改动。
