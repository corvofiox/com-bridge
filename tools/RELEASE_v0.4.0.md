# Com Bridge v0.4.0

界面彻底重做 + 全新品牌图标。功能与 v0.3.1 一致（键鼠跨屏、音频同步、静默自启、
副机等待握手、Ctrl+Alt+Esc 逃生通道），这一版集中解决"界面难看"的问题。

## 界面：从零重做，两套配色

旧界面被判定为"像初学者做的"。复盘后确认问题不在配色，而在结构，逐条修掉：

| 旧问题 | 现在 |
|---|---|
| 620×660 里只有四行设置，中间空 170px | 窗口高度**按内容计算**，内容多少窗口就多高 |
| 到处是圆角卡片 + 投影 + 渐变，碎片化 | 白纸 + 卡片 + **真实高斯阴影**，层次分明 |
| 字号几乎一样大，没有层级 | 明确四档字号，状态词最大 |
| 状态是一整块彩色底 | 状态用**胶囊 + 颜色**表达，不占面积 |

**两套配色**，顶栏按钮即时切换，记忆选择，默认跟随 Windows 深色模式：

- **深色**：炭黑底 + 悬浮卡片 + 蓝色强调
- **浅色**：浅灰蓝底 + 白卡片 + 靛蓝强调

## 一处真实的技术缺陷（影响所有旧版本）

**文字一直"发虚"**。原因是把文字画在 4 倍超采样画布上再降采样 —— 图形边缘是平滑了，
但文字细笔画被平均掉。实测：蓝底白字在白字区域**没有任何一个像素超过 245**。

现在改成"图形先降采样、文字再按最终分辨率绘制"：

| | 修复前 | 修复后 |
|---|---|---|
| 蓝底白字 | 0 个纯白像素 | 274 |
| 状态文字 | 111 | 248 |
| 分段控件文字 | 57 | 355 |

这大概也是旧版"整体发灰、不干净"的原因之一。

## 品牌图标：全新「H」

两根竖柱 + 一条横杠 = 两台电脑 + 一条链路。

几何**只在 `com_bridge/brand.py` 定义一次**，四处共用（窗口 / exe / 托盘 / 主界面），
避免各自漂移——此前四处各写一套，实测已经差了一个像素。

- `.exe` 图标：7 档尺寸 16/24/32/48/64/128/256
- 托盘图标：单色剪影 + 状态圆点，随任务栏明暗自动反白
- 生成器自带形状自检（柱身必须是两段、横杠必须连通），不合格则非零退出

## 播放 / 停止按钮

底部整行的大按钮换成两个纯图形按钮，放在状态卡右下角。**无底色**，颜色即状态：

| 状态 | 播放三角（左） | 停止方块（右） |
|---|---|---|
| 未启动 | 黑 | **红** |
| 运行·等待连接 | **黄** | 黑 |
| 运行·已连接 | **绿** | 黑 |

顺带修掉一个逻辑错误：旧版「已启动但还没连上」也会显示成绿色。

## 状态窗口 / 日志窗口

两个次级窗口按新设计语言重做（卡片、图标徽章、胶囊按钮）。

**修复一个数据读取回归**：状态窗口"一行数据都读不出来"。根因是
`status_dot().set_color()` 参数名被改、调用方仍用旧名 → 抛 TypeError →
被定时刷新的 `except: pass` 吞掉。现在异常会写进日志窗口，不再静默。

## 其它修正

- 「延迟目标」输入框曾显示 `60.0`（配置里是 float）→ 现在显示 `60`
- `ms` 单位紧贴边框 → 改为按文字实测宽度 + 固定 8px 右内边距
- 主界面「缓冲」改为「**音频缓冲**」并用括号挂在连接状态后，避免被误读为整条链路的连接延迟
- 状态窗口键盘文案与实际采集路径同步：主电脑的键盘走**低级钩子**而非 RawInput

## 升级说明

- 配置文件新增 `ui_theme` 字段（`auto` / `light` / `dark`），旧配置自动兼容
- 下载 `com-bridge-gui.exe` 直接替换即可，无需其他步骤
- 主副机**都需升级**才能获得新界面（协议未变，可与 v0.3.1 互通）
